# 维护与路线图

## 1. 分支模型

| 分支 | 用途 |
|---|---|
| `main` | 原始基线、课程文档、已验证内容 |
| `course/2026-midterm` | 2026 中期检查实现 |
| `course/2027-final` | 后续期末/大作业 |
| `feature/<topic>` | 单个功能 |

## 2. 标签

- `midterm-2026`：中期检查提交版本；
- `final-2027`：期末项目版本；
- 标签只指向经过测试的提交。

## 3. 中期检查后如何更新

1. 新建/切换到 `course/2026-midterm`；
2. 修复通信、姿态、直线/掉头问题；
3. 更新 `docs/06-midterm-3m-round-trip.md` 与测试记录；
4. 通过后合并到 `main`，打 `midterm-2026` 标签；
5. 在 GitHub Releases 上传 `.hex`（不提交到 Git）。

## 4. 期末项目如何扩展

1. 从 `main` 新建 `course/2027-final`；
2. 保持原始基线不动；
3. 新增功能放在独立目录/文件；
4. 新增实验页 `docs/11-final-*.md`；
5. 更新 README 索引与状态表；
6. 通过测试后打 `final-2027`。

## 5. 发布固件

- Git 只存源码；
- `hex` 通过 Releases 发布；
- Release 说明包含：
  - 目标板/Target；
  - 编译工具版本；
  - 已验证功能；
  - 已知问题；
  - 烧录方法。

## 6. 新增实验/文档

命名建议：

```text
docs/NN-lab-<topic>.md
firmware/experimental/<board>-<feature>/
```

每个实验页包含：

- 目标与验收标准；
- 原始资料依据；
- 接线/参数；
- 实现步骤；
- 测试步骤；
- 故障排查；
- 验证状态。

## 7. 学生使用方式

1. 克隆仓库；
2. 先读 `README.md` 与原始工程；
3. 按 `docs/` 顺序做实验；
4. 在自己的分支上修改；
5. 提交测试记录/PR；
6. 不直接改 `firmware/original/`。

## 8. 评审清单

- [ ] 原始工程未被覆盖；
- [ ] 实验代码有“未验证/已验证”状态；
- [ ] 协议两端一致；
- [ ] 车型参数与实际硬件一致；
- [ ] 无构建产物/大文件；
- [ ] 文档、接线、测试记录齐全；
- [ ] 安全注意事项明确。
